## 1. Problem statement

Horos classifies token sinks and writes the reading boundary agents consult
before reading a repository. One of its content rules scans the first 4096
bytes (and, for large unresolved files, two later 2048-byte windows) for six
generated-file markers: `do not edit`, `@generated`, `code generated by`,
`auto-generated`, `autogenerated`, `automatically generated`
(`GENERATED_MARKERS`, `horos.py` lines 61-68). The rule matches the marker
anywhere in the decoded text, so the classifier's own source binds itself: the
tuple that defines the markers puts `do not edit` inside the first 4096 bytes
of `horos.py`, and the test fixtures in `test_classify.py` do the same. The
committed boundary at the starting ref records both:
`plugins/horos/skills/horos/scripts/horos.py` at 42,541 bytes and
`plugins/horos/tests/test_classify.py` at 16,991 bytes, both
`marker 'do not edit' in the first 4096 bytes`, grade hard. That is 59,532
bytes of first-party source excluded from ordinary agent reading, which is the
shape the security-review carve-out exists to prevent, and it is the evidence
that reopened the frontier (ledger row horos-v9.2.3).

Who this serves: any agent that consults a committed boundary before reading,
and the maintainer who must trust that the boundary never hides the tool that
produced it.

What is being built: a narrower binding condition for the marker rule, in both
the prefix pass and the window pass, such that a marker binds only when its
occurrence sits on a comment-led line. The new condition accepts a strict
subset of what the old one accepted, so no file gains an exclusion.

A working prototype means, over this repository at the run head:

- `python3 plugins/horos/skills/horos/scripts/horos.py scan . --json` emits no
  entry for `plugins/horos/skills/horos/scripts/horos.py` and none for
  `plugins/horos/tests/test_classify.py`, while it keeps the entries for
  `CONTRIBUTORS.md` (a genuinely generated file whose banner is an HTML
  comment) and `plugins/horos/examples/fixture/gen/api.py` (a `#`-led banner).
  A named test pins all four facts.
- Near-miss tests pin that genuinely generated files still bind: comment-led
  banners across the `#`, `//`, `/*`, `*` continuation, `<!--`, `--`, `;` and
  `%` leader families, in the prefix pass and in the window pass, and that a
  marker inside a string literal, a call argument or a JSON value stays
  readable in both passes.
- `python3 -m unittest discover -s plugins/horos/tests -t plugins/horos`
  passes, `python3 -m unittest discover -s tests` passes against the
  regenerated `.horos/boundary.json`, and
  `python3 plugins/horos/skills/horos/scripts/horos.py check .` exits 0.
- The marketplace-prose reconciliation step finishes with
  `python3 -m unittest tests.test_marketplace_prose` green and the cold-read

The demo path is those commands, run in that order from the repository root.

## 4. Design options

Four candidate constructions were weighed. A prototype of option 1 was run
over the eight marker-evidence entries in the committed boundary; its table
follows the options.

1. **Line-anchored comment-leader gate (chosen).** A marker binds only when
   its occurrence sits on a line whose first non-whitespace characters are a
   comment leader from a fixed, language-independent set: `#`, `//`, `/*`,
   `*` (block continuation), `<!--`, `--`, `;`, `%`. The same gate runs in
   the prefix pass and the window pass; the window pass evaluates only lines
   wholly contained in the window, so an offset landing mid-line cannot
   manufacture or split a match. Roughly fifteen lines of code, no lexer, no
   per-extension table, deterministic on any byte sequence. Trade: it gives
   up exactness in both directions. A generated file whose only marker sits
   in a docstring or trailing text stays readable (fail-open, tokens lost,
   nothing hidden), and a multi-line string whose content line begins with a
   comment leader would still bind (no such line exists in this tree; the
   repository-level test in section 1 pins that and would name any future
   one).
2. **Extension-keyed comment-span lexing.** Reuse the Imprimatur approach:
   exact comment spans per language, marker binds only inside a span. Exact,
   but the Imprimatur run needed eight audit rounds of lexer-state repairs to
   make three languages honest, and the classifier would need that fidelity
   over every extension it meets, inside a scanner whose contract is bounded
   cheap heuristics. Rejected: the comprehension and audit cost dwarfs the
   defect, and a wrong lexer state silently reopens the self-exclusion.
3. **Quote-enclosure heuristic.** A marker occurrence does not bind when
   quote characters enclose it on its line. Cheaper than option 2, but
   apostrophes in prose ("don't edit this auto-generated file") flip its
   answer, and a marker inside a multi-line string is invisible to it because
   the enclosing quotes sit on other lines. Rejected: its failure cases are
   harder to reason about than the ones option 1 accepts.
4. **Self-path allowlist.** Exempt the classifier's own paths. Rejected: it
   special-cases the symptom, generalises to no other repository, and a
   path-keyed exemption is exactly the invited-exclusion shape the rules are
   written to avoid (`horos.py` line 81 already refuses name-keyed trust for
   the content-addressed rule for the same reason).

Option 1 is the pick: the cheapest to comprehend that still meets the problem
statement, and the only one whose wrong answers are all fail-open.

## 5. Risk register seed

```risk-register
window-partial-lines | the window pass reading 2048 bytes at arbitrary offsets | windows evaluate only lines wholly contained in the window, pinned by a test that straddles a banner across a window edge
string-at-line-start | a multi-line string literal whose content line begins with a comment leader | named residual; the repository-level zero-self-exclusion test pins this tree and names any future offender
comment-invited-exclusion | a repository writing a fake banner comment to invite exclusion | unchanged declared semantics; the security-review carve-out in SKILL.md is the control and must stay untouched
monotone-narrowing | the set of files the marker rule binds | a test asserts the new rule's matches are a subset of the old rule's over the fixture corpus and this tree
boundary-regeneration | the committed .horos/boundary.json against the changed rule | rule change and regenerated boundary land in one step; tests/test_boundary_currency.py is the guard in both directions
recall-loss-docstring | generated files whose only marker sits in a docstring or trailing text | fail-open, the file stays readable; near-miss tests pin every comment-led form so the loss is bounded to non-comment-led banners
evidence-wording | the evidence string other tools and committed boundaries carry | the new wording is asserted by tests; external repositories re-mark in their own runs
prose-reconciliation | mutable first-party marketplace prose against the post-run state | a dedicated late step cold-reads and reconciles it; tests/test_marketplace_prose.py must pass
corroboration-flow | directory corroboration sampling, which calls classify_content | the narrowed rule flows into directory sampling; a test pins that a candidate directory corroborated only by string-literal markers no longer excludes, and the four sample-corroborated entries in this tree (verified geometry-based) stay put
```

The audit loop should look hardest at the window pass (offset arithmetic and
partial lines are where a deterministic claim quietly stops being one) and at
the monotone-narrowing claim, because it is the argument that no repository
anywhere gains an exclusion from this change.

## 6. Glossary seeds

- Marker: one of the six phrases in `GENERATED_MARKERS` whose presence
  declares a file generated.
- Comment-led line: a line whose first non-whitespace characters are one
  of the fixed comment leaders (`#`, `//`, `/*`, `*`, `<!--`, `--`, `;`, `%`).
- Self-exclusion: a boundary entry that excludes a file because the file
  defines or fixtures the rule that matched it.
- Monotone narrowing: a rule change whose new match set is a subset of
  the old one, so no file gains an exclusion.
- Near-miss test: a fixture one feature away from the excluded shape,
  pinning that the rule still binds what it must.
- Prefix pass and window pass: the 4096-byte head read every file gets, and
  the two 2048-byte reads a large unresolved file gets.
- Universe: the file set a scan classifies; `tracked` by default.
- Boundary currency: the committed boundary matching a fresh scan of the
  tree it ships with, held by `tests/test_boundary_currency.py`.

## 8. Signals, and the questions behind them

Two questions get asked of a boundary after the fact, and both must be
answerable from what the tool already emits; [ephoros](../../../hexaemeron/skills/ephoros/SKILL.md)
owns what a signal must carry.

- "Why is this file excluded?" The entry's evidence string answers it, so the
  new wording must name the condition that actually held, e.g.
  `marker 'do not edit' on a comment-led line in the first 4096 bytes`. A
  test asserts the wording.
- "Is the committed boundary current?" `check` exit codes (0 current, 1 drift
  with every path named, 2 no usable boundary) and
  `tests/test_boundary_currency.py` answer it; both already exist and this
  change must keep them exact.

No alerting or metrics beyond that, and here is why: horos runs from a
terminal at a person's request, never unattended, so the exit code and the
evidence strings are the whole observable surface.

## 9. Boundaries, per capability

[phylax](../../../hexaemeron/skills/phylax/SKILL.md) owns the boundary list and the controls; this
change opens no new one and narrows an old one.

- Untrusted repository bytes into the scanner: reads stay bounded (4096-byte
  prefix, 2048-byte windows, decode with replacement), symlinks stay refused
  in walk and in `classify_file`, and nothing inspected is executed. What is
  worth taking at this boundary is an exclusion: a repository author writing
  bytes that make a reviewer-relevant file unreadable to agents. The change
  narrows that take: a string literal no longer works, only a line-led
  comment banner does, which is the same declaration any generated file
  makes. The remaining take is controlled by the carve-out this run must not
  weaken: no boundary applies during security review (SKILL.md, refusals
  list).
- Subprocess: the existing pinned-argv `git ls-files` calls are untouched; no
  new subprocess, no shell, no network, no secret material anywhere in this
  path.

## 11. The fail-closed posture

[elenchus](../../../hexaemeron/skills/elenchus/SKILL.md) owns the triage order and the guard rule;
this run adopts them as follows. A red suite at either level stops the line:
nothing merges over a failing root or horos suite, and a drifted committed
boundary is a red suite by construction
(`tests/test_boundary_currency.py` names the paths in both directions).
Classification itself keeps its two postures unchanged: fail-open for
unevidenced files (they stay readable) and fail-closed for unreadable ones
(counted in `files_skipped_unreadable`, never reported readable). Every fix
an audit round claims lands with a guard test that fails without it, in
`plugins/horos/tests/`, following the suite's existing naming
(`test_<behaviour>` sentences); the near-miss fixtures in section 1 are the
first such guards and must be observed red against the unfixed rule before
the fix lands.
