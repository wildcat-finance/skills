## 1. problem statement

Gate 1 of the Berean release contract says every factual sentence carries one
source class. Three of the four classes must then name evidence that is
checked: a `document` sentence cites ids that re-slice against the pinned
corpus, a `chain_read` sentence cites ids that resolve to preserved read
records at the declared chain and block, and a `calculation` sentence derives
from ids already in the answer. The fourth class is checked the other way
round. `answers.py` refuses a `user_supplied` sentence that cites anything at
all, and constrains it in no other way. The answer document below passes
`check-answer` today:

```json
{
  "text": "So the flag will certainly stay set next quarter.",
  "source_class": "user_supplied",
  "evidence": []
}
```

That sentence is the same unsupported inference the fixture's `c-inference`
case exists to see refused, with its class changed from `calculation` to
`user_supplied`. Reclassified, it passes every mechanical gate, and gate 6's
"reclassifies evidence" failure catches it only where somebody wrote that
adversarial case. The record already requires `question`, so the binding the
class lacks is already on the page: a supplied fact came from the asker, and
the asker's words are the one thing it can rest on.

The users are release authors running `check-answer` and `verify-release`
over recorded answers, reviewers grading a release through `run-evals`, and
the first Wildcat-grounded release the ledger holds as its next job, whose
answers will carry real supplied facts rather than fixture prose.

A working prototype means:

- A `user_supplied` sentence names at least one span of the recorded
  question, and each span re-slices to real, whole, non-blank bytes of it.
- A `user_supplied` sentence that names nothing, names a malformed or
  out-of-range span, splits a character, points at whitespace, or cites a
  citation or read id fails `answer-shape` with a reason naming the sentence.
- `document`, `chain_read` and `calculation` resolution, refusal emptiness,
  the retention count and every named gate list are unchanged.
- The synthetic conformance fixture is regenerated by its builder, holds a
  bound `user_supplied` sentence and one `rejected` case carrying the
  reclassified one, and its committed bytes equal the builder's output.
- The reference release under `examples/goldfinch-demo-v0/` does not change
  by one byte.
- The ledger records `berean-v0.2.0`, the skill frontmatter matches it, the
  package version is `0.1.2` on every surface, and the prose that describes
  the rule says the new rule.

## 4. design options

### option A: span references in the existing evidence list (chosen)

A `user_supplied` sentence lists one or more strings of the form
`question:<start>-<end>` in `evidence`. The checker parses each with a fixed
grammar, then re-slices `question.encode("utf-8")[start:end]` and requires
the range to be in bounds, non-empty, whole UTF-8 and non-blank. A sentence
with an empty list fails; a sentence naming a citation or read id fails as it
does today. Citation and read ids beginning with `question:` are refused
when collected, so one evidence string resolves to one kind of thing
whichever sentence cites it.

The grammar is `^question:(0|[1-9][0-9]{0,6})-(0|[1-9][0-9]{0,6})$`:
canonical decimals with no sign, no leading zero and at most seven digits.
Seven digits cover any offset into a document under the 4 MiB `jsonio`
ceiling, and bounding them before `int()` runs makes 3.9.6 and 3.12.13 refuse
an oversized digit run the same way. `end` must exceed `start` and must not
exceed the encoded length of `question`. The fixture's committed sentence
would name `question:7-21`, the bytes of "pause flag set" in "Is the pause
flag set?".

The check lives in `validate`, so a failure is `answer-shape`, for the same
reason citation-id resolution already lives there: the question is in the
document being validated, and it cannot drift from itself the way a corpus
file on disk can drift from its manifest. Citations earn a separate named
check because they touch an artefact outside the record; a question span
touches nothing outside it. Diagnostics name the sentence index and the
position of the reference in the list, plus the parsed start and end where
the reference parsed and the encoded question length where the range left
it; a reference that did not parse is not repeated, and the question bytes
and the decoded span never appear.

Byte offsets, not characters: citations already count bytes of UTF-8, the
decode-and-refuse idiom is written and tested, and one integer meaning two
units in one document is the kind of ambiguity a closed format exists to
refuse. Bytes are also the one unit every runtime agrees on.

What the mechanical check proves: the sentence points at real, whole,
non-blank bytes of the asker's question. What it does not prove: that the
sentence rests on them in any honest sense. That stays with gate 6 and the
eval corpus, which is why assumption 7 puts the reclassified case there.

The trade. This construction changes the meaning of `evidence` for one
class from "must be empty" to "must name question spans", so a reader of the
schema alone cannot see the rule and has to read `docs/answers.md` or the
schema description. A span carries no display text and no digest; that
costs less than it does for citations because the question is in the same
document, so slicing by hand is possible and a digest over bytes already
present would prove nothing. And the label stays `v1` while a record with an
evidence-free `user_supplied` sentence changes from accepted to refused,
which the issue calls for and which touches only the regenerated fixture.

### option B: a per-sentence field

Add `question_spans` to every sentence as a list of
`byte_start`, `byte_end`, `display_text` objects. It is self-describing, but
`SENTENCE_FIELDS` is a closed required table and the schema refuses unknown
keys, so every sentence in every document changes shape, including the
reference release's answers and cases, whose digests, `release.json` and
promotion record would all move. That is a format change to
`berean-answer/v1` in everything but the label, and the issue rules it out.

### option C: a top-level span artefact

Add a `question_spans` list beside `citations` and `reads`, each entry with
`id`, `byte_start`, `byte_end` and `display_text`, cited by id from
`evidence`. It is the most symmetric shape: every class then resolves ids to
exactly one artefact and the check reads like `citations.check`. But
`FIELDS` and the schema's `required` change, so every answer document
including refusals and the reference release gains a key, with the same
cascade as option B. It is the natural shape for a `v2` if one is ever
minted, and this study records it as that rather than choosing it.

### option D: a whole-question token

Let a `user_supplied` sentence carry the single token `question` in
`evidence`, meaning "rests on the recorded question". Nothing to parse, but
nothing proved either: a sentence resting on "the whole question" is the
unconstrained class with a longer name, and the reclassified inference above
would pass exactly as it does today.

Option A is the cheapest to comprehend that still meets the problem
statement: one regex, one slice, one reserved prefix, in the function that
already resolves evidence per class, with the schema file untouched. It gives
up a self-describing schema and span display text in exchange for keeping
every committed record outside the fixture byte-identical. Option B and C
pay a format change the issue forbids; option D pays nothing and buys
nothing.

Settled alongside the pick:

- Only `kind: answer` documents carrying a `user_supplied` sentence are
  affected. Refusals are enforced sentence-free and are untouched.
- `release-retention` is unchanged; it counts `source_class`, not
  `evidence`.
- `evals.grade` is unchanged; a sentence that names nothing now fails
  `answer-shape`, so a `rejected` case built on it passes by the existing
  rule. `evals.export` gains one assertion string under `grounded-answer`,
  "every user-supplied sentence names the spans of the recorded question it
  rests on", because the exported list is the rule set an external runner
  reads; no committed export file exists, so no bytes are re-pinned.
- The synthetic fixture gains `c-reclassified`: expectation `rejected`,
  adversarial `unsupported-inference`, embedding the grounded answer with
  the `c-inference` sentence reclassified as `user_supplied` with an empty
  list. The fixture's case count moves from 6 to 7 and
  `test_the_fixture_corpus_grades_clean_and_reproduces_its_report` moves
  with it.
- Prose that states the rule and changes: `docs/answers.md` (the
  `user_supplied` bullet and the grammar), `SKILL.md` gate 1 and the
  `berean-answer-evidence` refuses clause, the schema `description`
  sentence. `plugins/berean/README.md` line 30 says the rules separate
  user-supplied facts from the other three classes, which stays true, so it
  does not change; the root `README.md` does not describe the rule.
- No ADR. The decision belongs to one governed skill, so the
  `berean-v0.2.0` ledger row is its standing record; section 12 has the
  detail.

## 5. risk register seed

```risk-register
untrusted-answer-json | answer documents entering validate through jsonio | size depth duplicate-key and float refusals stay in front of the span parser and no new read path bypasses jsonio
span-grammar | evidence strings of a user_supplied sentence | only canonical question:<start>-<end> with at most seven digits parses and every other spelling fails answer-shape before int runs on either interpreter
span-bounds | byte offsets against the UTF-8 length of question | inverted empty and past-the-end ranges fail and the check never slices beyond the encoded question
span-utf8 | a range that cuts a multibyte character | the decode failure is a named answer-shape reason with a multibyte guard on both interpreters
span-blank | a range decoding to whitespace only | a whitespace-only span fails the way a blank stated field fails
artefact-ref-refused | a user_supplied sentence naming a citation or read id | the berean-v0.1.0 refusal stands and its guard test survives the rename
id-prefix-collision | citation and read ids spelled like a span reference | an artefact id beginning with question: is refused at collection so one string resolves to one kind of thing
diagnostic-output | answer-shape details rendered by check-answer verify-release and run-evals | details carry the sentence index reference position and parsed offsets and never the question bytes an unparsed reference or the decoded span
other-classes-unchanged | document chain_read and calculation resolution and refusal emptiness | every existing test_answers verdict holds and the named check lists of answers.check and release.verify are unchanged
fixture-regeneration | the committed pass-release directory | the builder output equals the committed bytes file for file and every digest in release.json is the builder's
report-consistency | evals/report.json inside the regenerated fixture | the report is earned by grading inside the builder and run-evals reproduces it with seven cases
goldfinch-untouched | the shipped reference release | no byte under examples/goldfinch-demo-v0 changes and its rebuild drift and demo tests stay green
coverage-pin | the berean-answer-o selector in tests/promise_machine_coverage.json | the selector resolves to the renamed test and promise_machine.py check prints clean
ledger-integrity | the berean-v0.2.0 generation row | revision and digest are byte-identical to v0.1.0 the Next Fiat job text is unchanged and SKILL.md metadata.version matches
version-surfaces | the three package manifests and two version pins | every surface states 0.1.2 and the scaffold and root propagation tests pass
partial-run | an interrupted regeneration test or lint | no fixture commit receipt or clean claim rests on a command that did not exit zero
```

There is no subprocess, network fetch, secret, dependency or filesystem write
in the verifier change; the only writes are the builder's, into the fixture
directory, run deliberately once. The input path stays `jsonio.load` and
`jsonio.loads`. The audit should look hardest at the grammar and bounds
lines, because a span check that passes on a blank, empty or split range is
the old hole with a new spelling, and at the diagnostic line, because the
one place question text could leak is a detail string.

## 6. glossary seeds

- `question span`: a byte range `[start, end)` into the UTF-8 encoding of an
  answer record's `question` field.
- `span reference`: the string `question:<start>-<end>` naming a question
  span from a `user_supplied` sentence's `evidence` list.
- `reserved prefix`: `question:`, which no citation or read id may begin
  with, so a span reference and an artefact id never share a spelling.
- `re-slice`: recomputing bytes from offsets and comparing the result, the
  check citations make against the corpus and spans make against the
  question.
- `answer-shape`: the named check that fails when an answer document
  violates its tables, vocabularies or intra-document resolution, including
  span resolution.
- `reclassified case`: the fixture eval case `c-reclassified`, whose embedded
  answer carries the unsupported inference under the `user_supplied` class
  and expects the checker to refuse it.
- `generation row`: a ledger row that changes behaviour while retaining the
  frontier revision, digest and next job byte for byte.

## 8. signals and the questions behind them

`plugins/hexaemeron/skills/ephoros/SKILL.md` adds no telemetry gate here.
Berean is a local CLI that reads files and exits; nothing runs unattended
and no event, metric, trace or alert is warranted. The step keeps the two
signals the CLI already emits and tests them for the new refusal:

1. "Which sentence was refused, and why?" `check-answer` prints
   `fail  answer-shape: <detail>` with the sentence index, the reference
   position and the parsed offsets; `verify-release` carries the same detail
   under `release-answers` prefixed by the answer path; `run-evals` prints it
   as the reason a `rejected` case passed.
2. "Did the check run to the end?" Exit 0 with `all checks passed`, exit 1
   with `refused: N check(s) failed`, exit 2 for a usage or read error. An
   interrupted command supplies none of these.

## 9. boundaries per capability

`plugins/hexaemeron/skills/phylax/SKILL.md` governs the capability. The
boundary is an untrusted answer document, already read through `jsonio`'s
caps, reaching a new parse and slice in `validate`. Worth taking there: a
crash in the checker from an oversized digit run or an unexpected type, and
a pass on a span that points at nothing. The controls are regex-first
parsing with bounded digits, an explicit bounds check before the slice, a
decode check and a blank check, each with a red-then-green guard; the risk
ids `untrusted-answer-json` through `span-blank` enumerate them.

The second boundary is the namespace shared by artefact ids and span
references. Worth taking: one string that resolves two ways depending on
which sentence cites it. The control is the reserved prefix, refused where
ids are collected; `id-prefix-collision` names the check.

The third boundary is output. Worth taking: question text or a decoded span
in a diagnostic, which `verify-release` and `run-evals` print and which a
release with `retention: none` may not want reproduced anywhere. The control
is that details carry indices, positions and integers only, and a test
asserts the question text is absent; `diagnostic-output` names it.

No new host, dependency, subprocess, network path, secret, model output or
persistent write is introduced. The builder's write into the fixture
directory is the same staged, canonical write it makes today.

## 10. budget or its absence

`plugins/hexaemeron/skills/metron/SKILL.md` has no gate here. Issue #331
makes no latency, memory or throughput claim, and the chosen design adds one
regex match and one slice per span reference over a question already held
in memory, bounded by 500 sentences and the 4 MiB document ceiling. No
speed-motivated change is authorised, so there is no baseline to record and
no measuring command to name. The suite commands are correctness gates, not
benchmarks.

## 11. fail-closed posture

`plugins/hexaemeron/skills/elenchus/SKILL.md` governs the failures this run
will hold in hand. Each new refusal is first observed red against the current
`answers.py`: an empty list on a `user_supplied` sentence passes today and
must fail; a malformed, out-of-range, split or blank span has no meaning
today and must fail by name; an artefact id must keep failing. The
reclassified eval case is the eval-level red: under the current checker its
`rejected` expectation fails because the checker accepts the answer.

What stops the step: a red test on either interpreter, a committed fixture
byte that differs from the builder's output, `promise_machine.py check` not
printing clean, the evolution contract test red, any non-zero lint, or any
non-zero command in the demo path. Existing unreadable or malformed documents
keep failing at `jsonio` or `answer-shape`; no new branch may turn an
incomplete check into a pass.

The guard convention: every refusal has a test in `test_answers.py` that
fails when the span check is removed, the renamed
`test_a_user_supplied_fact_names_the_question_spans_it_rests_on` keeps the
old refusal alongside the new binding so the coverage claim it carries stays
true, one release-level guard in `test_release.py` re-pins a blanked span
list and asserts `release-answers` fails naming `answer-shape`, and the
fixture's `c-reclassified` case is the end-to-end guard `run-evals` grades.
The runner contract Warden will hold a fix to is the Berean discover command
above, unittest text format, on both interpreters.

## 12. decisions and their homes

`plugins/hexaemeron/skills/hypomnema/SKILL.md` puts a decision about one
governed skill in that skill's ledger. The expensive-to-reverse decision here
is the spelling and unit of a span reference: once records in the wild carry
`question:7-21` strings in `evidence`, moving to a span artefact is a `v2`
format. Its standing record is the `berean-v0.2.0` row in
`plugins/berean/skills/berean/EVOLUTION.md`, whose change column names the
grammar, the byte unit, the retained refusal of artefact ids and the
rejected per-sentence and top-level constructions, and whose evidence column
links the guard tests and the committed study copy that holds the losing
options in full.

`plugins/berean/docs/answers.md` owns the vocabulary and gains the grammar
and what the check proves and does not prove. `SKILL.md` owns the public
gate text and the `berean-answer-evidence` promise, and gains one clause in
each; its `metadata.version` moves to `0.2.0` with the ledger. The schema
`description` gains one sentence so an implementer reading only the schema
learns that `evidence` on a `user_supplied` sentence resolves against
`question`. The package bump and its reason go in the step's commit message,
which is where this repository records what shipped.

No repository-wide ADR is warranted: the change adds no shared schema,
dependency, storage format or cross-plugin ownership decision, and Berean's
`docs/design.md` records the plugin's founding decisions rather than serving
as a second ledger. Exact committed copies of the receipted artefacts belong
at `docs/berean-question-spans/study.md` and
`docs/berean-question-spans/runbook.md`; the audit rounds go to the file Fiat
derives under `audit/rounds/`.

If implementation needs a new field, a new vocabulary value, a second named
check, a change to the reference release, a breach operation or a different
package version, amend this study before code. A generation row cannot
silently widen a format the frontier job has yet to ship against.
