# Study: one checked `sync-run` transition across a generator-owned payload

Status: ready for a runbook, subject to the assumptions below.

Controller brief: build “give sync-run one checked transition across a
generator-owned payload” from `main` in this target. The starting commit is
`bec742ac17a5fdd95f0242d2b7ba894828cebf22`.

Assuming, unless corrected:

1. “One transition” means a second, explicitly versioned integration
   revalidation schema consumed by the existing `done sync-run` command. It is
   not a new controller phase and does not weaken the signature, parent,
   remote-tip, GitHub-verification, or later `done integrate` gates.
2. Maintainer review is made executable by a source-controlled registry of
   exact generator-owned prefixes. An artefact cannot declare ownership for
   itself, and there is no runtime override.
3. The first and only registered aggregate is the complete
   `.agents/skills/promise-machine/runtime/` tree generated by
   `scripts/portable_promise_machine.py`; `MANIFEST.json` is part of that tree
   even though it cannot list its own digest.
4. The ignored #622 revalidation artefact and the checkpoint named in issue
   #710 are not present in this checkout or reachable Git objects. The exact
   merge commits and path inventory are available. Acceptance therefore uses a
   deterministic reconstruction with the same 1,095 paths and topology, not a
   claim that the unavailable ten command records were independently read.
5. The aggregate proves the generator's complete final tree, not only the
   changed members. This deliberately binds a little more evidence in exchange
   for one stable ownership and verification boundary.
6. `fiat-integration-revalidation/v1` remains accepted byte-for-byte and keeps
   its existing 500-path behaviour. Existing small fixtures do not migrate.
7. The halted #622 run remains immutable. This run builds and tests the
   controller transition only; recovery or mutation of #622 needs separate
   authority after the transition ships.
8. Repository commands use the interpreter pinned by `.python-version`
   (`3.13.15`), not the ambient `python3` currently resolving to 3.14.

## 1. Problem statement

Fiat maintainers and operators need `done sync-run` to receipt one real base
advancement whose affected surface contains a large, generator-owned payload,
without turning the 500-path safety bound into a general larger allowance.
Today the #622 composition is valid enough to reach revalidation, but the
controller stops before it can reason about ownership because each of its Git
path inventories is capped at 500. The portable runtime accounts for 887 of
the 1,095 required paths; the other 208 paths still fit the individual bound.

A working prototype has all of these observable properties:

- Replaying the issue topology with a v1 artefact and 1,095 individual paths
  exits 2 with `integration path delta exceeds 500 paths`, exactly as the
  current controller does.
- The same topology under `fiat-integration-revalidation/v2` receipts one
  declared 887-file portable-runtime aggregate plus the 208 individual paths,
  and the fixture can then receipt `done integrate`.
- Wrong aggregate count, manifest digest, tree digest, changed or added prefix
  member, undeclared prefix, uncovered aggregate, and missing outside path all
  exit 2 before `state.json` or `ledger.jsonl` changes.
- Every existing v1 sync fixture under 500 paths still receipts without
  changing its fixture bytes or normalized receipt shape.
- The complete controller suite passes with the repository-pinned interpreter:
  `python3.13 plugins/hexaemeron/tests/run_tests.py`.

The proving demo is a checked-in issue-710 fixture and focused tests named for
the five acceptance groups above, exercised by that suite. The full repository
confirmation is `python3.13 -m unittest discover -s tests` followed by
`python3.13 scripts/portable_promise_machine.py check` after generated copies
are refreshed.

### Outside the organisation

Git's [data model](https://git-scm.com/docs/gitdatamodel.html) and
[user manual](https://git-scm.com/docs/user-manual) define a tree as names,
modes, object types, and object identifiers recursively bound by the commit.
That is useful commit evidence, but a Git object id is not the portable
per-file SHA-256 inventory required here. The
[TUF specification](https://theupdateframework.github.io/specification/v1.0.26/)
uses target lengths and hashes plus path-scoped delegations. Its applicable
lesson is that ownership is an independently trusted path rule, not a pattern
supplied by the payload being checked.

## 4. Design options

**A. Restore #679's separate 4,096-path cap.** This is the smallest code diff
and accepts the incident. It trades away the requested ownership check: any
4,096-path surface becomes admissible, and a later maintainer cannot tell a
generated atomic payload from unrelated sprawl. Rejected.

**B. Split the upstream advance into hops or shard the artefact.** This keeps
each list under 500. It trades away the exact product-first, current-base sync
topology and cannot cross #677's atomic merge because each hop recomputes an
upstream set containing the same 887-path addition. Rejected as non-working.

**C. Let v2 artefacts declare prefix patterns and generator commands.** This
is flexible and avoids controller releases for new generators. It trades away
maintainer review and lets untrusted evidence choose the boundary and the
command said to validate it. Rejected.

**D. Add one v2 aggregate form backed by a static generator registry and the
pinned manifest. Chosen.** It adds a small schema/version branch and a bounded
Git-object reader. The deliberate trade is maintenance: each new generator or
larger resource envelope needs a reviewed source change. It is the cheapest
construction to comprehend that satisfies all five acceptance groups, because
authority, evidence, coverage, and resource limits each have one named home.

The chosen construction is exact enough to implement as follows.

1. Keep the v1 parser and `git_diff_paths` route unchanged. Add
   `fiat-integration-revalidation/v2` with exact top-level fields `schema`,
   `affected_paths`, `affected_aggregates`, and `checks`. Individual paths keep
   `_manifest_paths` and its 500-entry cap.
2. Add one source registry entry named
   `promise-machine-portable-runtime-v1`. It fixes the prefix
   `.agents/skills/promise-machine/runtime/`, generator
   `scripts/portable_promise_machine.py`, manifest `MANIFEST.json`, manifest
   schema `promise-machine-portable-runtime/v1`, verification command
   `python3 scripts/portable_promise_machine.py check`, maximum 1,024 final
   files, and maximum 32 MiB of final file bytes. The ceilings are local to
   this reviewed owner; crossing either refuses and requires a registry review.
3. Each `affected_aggregates` entry contains exactly `id`, `prefix`,
   `generator`, `manifest`, `manifest_sha256`, `file_count`, and
   `tree_sha256`. Every value except the three digests/count must equal its
   registry entry; duplicates, nested or overlapping aggregates refuse.
4. For v2 only, read the three Git deltas with the existing 30-second and 2 MiB
   output bounds but without applying the 500-count rule before classification.
   Apply the existing safe, unique UTF-8 path validation to the complete set.
   More than 500 required paths are legal only when all excess paths fall under
   a selected registered prefix; required paths outside prefixes remain an
   exact, sorted, at-most-500 `affected_paths` set.
5. Read the manifest and prefix tree from the exact `sync_head` Git object, not
   the worktree. Require safe, sorted, unique manifest paths; exact schema and
   generator; `file_count` and `total_bytes` consistency; and an actual prefix
   path set equal to the manifest rows plus `MANIFEST.json`. Refuse symlinks,
   submodules, non-blobs, unsafe modes, or any resource ceiling breach. Use one
   argv-only `git cat-file --batch` reader to hash the exact blob bytes and
   compare every manifest row's byte count and SHA-256, with deadline, declared
   total, and hard aggregate ceilings enforced while streaming.
6. Treat the manifest as the 887th row, using the artefact's
   `manifest_sha256`. For every final file, compute
   `SHA256("fiat-generator-file/v1\\0" || path_utf8 || NUL || mode_ascii || NUL ||
   decimal_byte_count || NUL || file_sha256_hex)`. Sort those per-file digests
   by full repository-relative path and compute
   `SHA256("fiat-generator-tree/v1\\0" || concatenated_raw_file_digests)`.
   The artefact's `file_count` and `tree_sha256` must equal the recomputation.
   Store the computed Git tree id beside these values in the normalized receipt.
7. A v2 check contains exactly `id`, `command`, `paths`, `aggregates`, and
   `exit`. Existing check count, id, command-size, exit-zero, and individual
   path caps stay unchanged. An aggregate is covered only when one check names
   its id and carries the registry's exact generator verification command.
   Individual coverage remains the union of `paths`; aggregate membership never
   covers a required path outside its exact prefix.
8. Perform every parse, Git/tree verification, digest comparison, coverage
   comparison, signature check, and GitHub check before the existing state and
   ledger write. Normalize the receipt with the exact individual inventory,
   aggregate evidence, check evidence, and computed product/upstream/overlap/
   composition counts so `status` and `verify` retain the decision.

This whole-prefix design covers deletion as well as addition: the required Git
delta says which owned path changed, while the final exact manifest/tree proves
what does and does not exist after the sync. It also explains why an added file
after artefact creation refuses: the exact path set, count, manifest equality,
or tree digest changes before mutation.

## 5. Risk register seed

```risk-register
general-cap-regression | v1 and ordinary integration path lists | the 500-path refusal and all existing small v1 receipt bytes stay unchanged
undeclared-owner | the artefact-to-registry authority join | only the exact source registry entry can authorize a prefix generator and command
aggregate-overreach | required paths at the selected prefix boundary | no aggregate covers a path outside its exact non-overlapping prefix
manifest-self-gap | the generated manifest which cannot hash itself | the artefact pins its bytes and count and tree digest include it as one file
manifest-tree-drift | manifest rows versus the exact sync commit tree | path set byte counts modes and SHA-256 values match every final blob
commit-worktree-confusion | immutable sync objects versus mutable checkout bytes | all aggregate evidence is read from sync_head Git objects
path-escape | Git and manifest path decoding | unsafe duplicate non-UTF-8 absolute parent and control-character paths refuse
outside-path-omission | required paths outside registered prefixes | exact individual equality and check coverage refuse every omission
check-coverage-gap | exit-zero command evidence versus aggregate ids | each aggregate is named by a check with the registry command and every individual is covered
schema-compatibility | v1 and v2 dispatch | v1 uses its existing parser route and the incident v1 error remains exact
resource-exhaustion | large Git metadata and blob streams | time output file-count and total-byte ceilings stop reads without partial receipt
subprocess-framing | argv-only Git batch protocol | malformed headers sizes object types short reads timeouts and nonzero exits refuse cleanly
receipt-mutation-order | validation failure before state and ledger append | every negative fixture compares state and ledger bytes before and after
incident-fixture-drift | reconstructed #622 topology in a checked-in fixture | exact commits path counts sorted inventory digest and runtime count are pinned and asserted
generated-copy-drift | canonical Fiat source and packaged runtime copies | generator check Promise coverage and Horos currency pass after one canonical edit
```

The audit loop should cite each id as reviewed or not applicable. The highest
attention belongs on authority joining, exact tree reconstruction, bounded
batch parsing, v1 compatibility, and byte-identical refusal state.

## 6. Glossary seeds

- **Affected surface:** sorted union of the sync composition paths and the
  product/upstream overlap paths already computed by Fiat.
- **Individual path:** one affected repository-relative path represented and
  covered under the existing 500-entry rules.
- **Generator aggregate:** one complete final tree under a statically registered
  prefix, represented by count, manifest digest, and tree digest.
- **Generator registry:** maintainer-reviewed controller source mapping one id
  to an exact prefix, generator, manifest contract, check command, and ceilings.
- **Pinned manifest:** `MANIFEST.json` bytes read from the exact sync commit and
  named by SHA-256 in the revalidation artefact.
- **Manifest self row:** the pinned manifest's own path, byte count, mode, and
  SHA-256 added to the per-file digest inventory outside the self-referential
  manifest rows.
- **Tree digest:** the domain-separated SHA-256 over path-sorted per-file
  digests, independent of the repository's Git object hash algorithm.
- **Owned required path:** an affected path whose exact path falls under one
  selected registered prefix, whether present or deleted in the final tree.
- **Outside path:** an affected path outside every selected aggregate; it must
  remain individually listed and checked.
- **Reconstructed incident fixture:** checked-in deterministic evidence derived
  from the exact #622 Git objects because the ignored operator artefact is not
  available.

## 8. Signals, and the questions behind them

[Ephoros](../plugins/hexaemeron/skills/ephoros/SKILL.md) owns the
signal contract. This controller gate should answer three operator questions:

1. **Which exact generator tree was accepted?** A successful `done sync-run`
   receipt and `status --json` expose schema, artefact SHA-256, aggregate id,
   prefix, generator, manifest SHA-256, file count, tree SHA-256, computed Git
   tree id, and sync commit.
2. **Why did the transition refuse?** The validation step emits one bounded,
   stable diagnostic naming the failing boundary and aggregate id when safe:
   schema, registry, manifest, path set, count, digest, resource, command
   coverage, or outside coverage. Refusal emits no receipt and the before/after
   state digests remain equal.
3. **Was every affected path accounted for?** The successful normalized receipt
   exposes required, aggregate-owned, and individual counts plus check ids; the
   implementation tests recompute that arithmetic from the stored inventories.

No new metric backend or network event sink is opened. The existing receipt,
ledger, status, exit code, and bounded stderr surfaces are sufficient for this
prototype; adding telemetry would be a separate boundary.

## 9. Boundaries, per capability

[Phylax](../plugins/hexaemeron/skills/phylax/SKILL.md) owns the
capability-boundary contract. The prototype opens or uses these boundaries:

- **Supplied JSON artefact:** worth taking schema-v2 declarations, individual
  evidence, aggregate evidence, and recorded checks. Close it with the existing
  bounded stable source read, strict duplicate-key JSON object shapes, scalar
  limits, safe paths, exact registry joins, and digest recomputation.
- **Git subprocess:** worth taking exact merge-base, diff, tree, and blob bytes
  for already-verified commit ids. Close it with argv-only calls, no shell or
  environment-derived ref, exact object types and sizes, batch-protocol parsing,
  time and byte ceilings, and refusal on partial/nonzero/malformed output.
- **Generator manifest:** worth taking per-file SHA-256, byte counts, and source
  inventory from the exact sync object. Close it with fixed schema/generator,
  safe unique rows, exact tree equality, actual blob hashing, explicit manifest
  self-binding, and aggregate-specific ceilings.
- **Static ownership registry:** worth taking one maintainer-reviewed authority
  statement. Close it by accepting no runtime additions, patterns, nesting, or
  overrides and by requiring a source review for every new owner or ceiling.
- **Controller state and ledger:** worth writing the normalized v2 receipt only
  after all existing and new gates pass. Close it with the existing atomic
  receipt path and byte-equality negative tests around every refusal class.

The existing signature and GitHub reads are used but not widened. The aggregate
validator needs no secret, network request, archive extraction, dynamic import,
or executable generator invocation.

## 11. The fail-closed posture

[Elenchus](../plugins/hexaemeron/skills/elenchus/SKILL.md) owns failure
triage and the guard convention. `done sync-run` stops before mutation on an
unknown schema or aggregate, any malformed or unsafe path, overlapping prefix,
Git read fault, manifest/tree mismatch, incorrect count or digest, ceiling
breach, nonzero or wrong generator command, uncovered aggregate, omitted
outside path, v1 over-limit surface, or any existing topology/signature/remote/
GitHub failure. It never falls back from v2 to v1, truncates a set, trusts the
worktree, or records partial aggregate evidence.

Every defect repair begins with a focused test that reproduces the wrong
acceptance or refusal on the parent implementation, then passes only after the
cause-level fix. For mutation-order defects, the guard captures the exact
`state.json` and `ledger.jsonl` bytes before the command and asserts equality
after exit 2. The issue-710 positive fixture stays paired with one-field-at-a-
time corruptions so a broad fixture rewrite cannot make red and green evidence
move together.

Recovery remains inspection-only: `verify`, `status`, `next`, exact Git-object
inspection, and fixture repair remain available. A stopped #622 run is not an
input the tests mutate.
