### Protasis declaration

Add an optional column-zero, isolated `audit-applicability` JSON fence with schema `protasis-audit-applicability/v1`. It is absent only when no attempted marker exists. An indented, malformed, duplicate, partial or unterminated marker refuses. Apply the same bounded strict-JSON, portable-path and no-follow reading rules used by the existing inventory; never fall back from a malformed declaration to the legacy path.

Its closed fields are `schema`, `source_views` and `entries`. `source_views` must equal the checked known-failure inventory's complete source/view set, including each id, path and both SHA-256 values. An applicability declaration therefore requires a clean known-failure inventory, including its explicit no-known claim when empty. The declaration does not add an untracked source route or weaken source freshness.

Each entry has exactly `id`, `source_ref`, `source_span`, `source_status`, `disposition`, `rationale`, `finding_id`, `criterion_id` and `tracking`. Ids are unique kebab-case strings. `source_ref` has the exact form `<source-id>:<detail>`: split at the first colon and require exact equality with one checked source id. The non-empty detail retains the original finding or lead locator and is otherwise opaque. `source_span` has exactly `start_byte`, `end_byte` and `sha256`; it selects one non-empty interval of the authoritative source, with UTF-8 boundaries and a matching digest. `source_status` is the exact bounded status text occurring in that span, or null when the source has no stated status. Null means unknown. `tracking` is a bounded list of canonical GitHub issue URLs already carrying the source concern; the checker does not open them or infer their current state. `rationale` records the reviewer judgment, including any distinction between an upstream issue and a target requirement.

Source spans preserve the cited bytes and stated status. Their presence does not establish that the span supports the rationale, that an older fix worked, or that the reviewer found every relevant source. Those remain review obligations. A claim of historical repair must retain the original fix/status evidence and qualifications; open and unknown upstream status remain open and unknown in the record.

The four dispositions are closed:

| Disposition | Required target | Permitted consequence |
| --- | --- | --- |
| `local-regression` | One `finding_id` in the clean known-failure capture; null `criterion_id`. | The existing parent-red and final-green route remains required. Every captured finding appears exactly once in this disposition. |
| `integration-requirement` | One `criterion_id` in the checked success-criteria join; null `finding_id`. | The target criterion remains pending until existing controller-owned execution settles it at its real consuming step. Several source concerns may share one exact criterion. |
| `historical` | Both target ids null; reason names the original repair evidence and its limits. | Preserve history. This supplies no current guard or success result. |
| `out-of-scope` | Both target ids null; reason names the unchanged boundary and any existing tracking issue. | Preserve the exclusion. This supplies no success result and erases no upstream concern. |

The consuming step and command are derived from the referenced existing capture or descriptor, never accepted a second time from the row. Unreferenced ordinary success criteria remain valid; the regression id set must match exactly. The declaration must retain the inventory's exact checked source/view set; an omitted or added source id refuses. This equality does not establish that the reviewer discovered every finding in those sources.

Read limits are 256 KiB per declaration-bearing document, 32 source/view pairs, 128 entries, 4,096 bytes per rationale or source reference, 1,024 bytes per status, eight tracking URLs per entry, 64 KiB per cited span, 2 MiB per source/view file and 16 MiB aggregate source/view bytes. Paths use the existing portable alias checks. Booleans do not count as byte offsets. Oversized, duplicate-key, non-finite, aliased, linked, replaced or unstable inputs refuse. Return an immutable absent/refused/clean result; clean captures canonical declaration and document digests, source/view rows, entries and derived routes. The checker writes no controller state and runs no declared command.

## 6. Glossary seeds

Applicability is the reviewer's source-bound decision about what a prior finding means for the named target. A local regression is an observed target failure requiring the existing guard route. An integration requirement is a new target obligation awaiting observed execution at its consuming step. A source witness is an exact digest-bound byte interval retaining status text. A route is the checked join from one applicability row to its owning evidence. Historical and excluded rows preserve knowledge and grant no current success.
