# Runbook: move the skills.sh payload to its own repository

Derived from `.hexaemeron/study.md`, which chose option A: the destination holds
a scheduled workflow that clones the public source, regenerates, verifies and
commits to itself.

Three steps, in dependency order. Step 2 makes the new address serve a working
install before step 3 stops this repository serving one, so no interval exists
in which neither address works. Step 1 scaffolds and carries the committed
copies of the study and runbook. Step 3 demonstrates, by installing from the
published destination and running the suite with the payload absent.

## Step 1: let the generator build a complete package anywhere

**Goal.** Teach `scripts/portable_promise_machine.py` to emit a complete,
installable package into a named directory, and make the package tests assert
against a tree it generates rather than one committed here.

**Entry.** The run branch `fiat/949-move-the-skills-sh-payload-to-its-own-reposi`
at its tip, cut from `main` at `bc38cbae49be7e16dde4e3f54a1e1bc21c5c4fc8`. The
tree is clean and `python3 -m unittest discover -s tests` exits 0.

**Exit.** Four deliverables:

1. The generator accepts an output directory and writes a complete package
   there: the four authored files, the generated runtime, a `skills.sh.json`
   grouping `promise-machine`, and a `README.md` naming the exact source commit
   the package was built from. A path escaping its named root, or reached
   through a symlink out of it, is refused by name without writing.
2. `tests/test_skills_sh_package.py` keeps all eight existing guarantees by
   generating into a temporary directory and asserting there. No guarantee is
   dropped or weakened, and the in-tree payload is still checked while it exists.
3. Committed copies of the study and runbook under `docs/`.
4. `.horos/boundary.json` regenerated.

Proved by `python3 -m unittest discover -s tests` exiting 0, and by
`python3 plugins/horos/skills/horos/scripts/horos.py check .` exiting 0.

**Files.** Changed: `scripts/portable_promise_machine.py`,
`tests/test_skills_sh_package.py`, `.horos/boundary.json`. Created:
`docs/skills-runtime-split-study.md`, `docs/skills-runtime-split-runbook.md`.

**Tests.** `tests/test_skills_sh_package.py` gains coverage for the output
directory: a generated package is complete and self-consistent, and an escaping
or symlinked output path is refused. Existing methods are rewritten to read the
generated tree, not added to. Expected count is at least the current nine.

Runner contract for an audit fix: the exact command is
`python3 -m unittest discover -s tests -v > {report} 2>&1`, run from the
repository root with one `{report}` argument. The report format is stdlib
`unittest` verbose text, not JSON; this repository ships no `unittest-json-v1`
runner, so a verdict read from it is textual. The report file is
`.hexaemeron/step-1-report.txt`.

**Disciplines.** phylax: applies, because the generator now takes a filesystem
path from a caller and must refuse one that escapes its root or traverses a
symlink out of it. ephoros: none, nothing this step produces runs unattended.
metron: none, no performance claim and no speed-motivated change. elenchus:
applies, because a red suite is worked to its cause under the runner contract
rather than by relaxing an assertion. hypomnema: none, the decision this run
makes is recorded in step 3 where the reversal lands.

## Step 2: publish the first package and prove it installs

**Goal.** Create `wildcat-finance/skills-runtime`, give it the scheduled job
that rebuilds itself hourly, publish the first package, and prove the documented
install works from it.

**Entry.** Step 1's branch, with the generator able to build a package into a
named directory and the suite green.

**Exit.** Five deliverables:

1. `wildcat-finance/skills-runtime` exists, is public, and holds a package
   generated by this repository's generator, including the `README.md` naming
   the exact source commit.
2. The destination holds `.github/workflows/sync.yml`, whose canonical copy is
   authored in this repository. It runs hourly and on manual dispatch, is
   guarded so it runs only in that repository, clones the public source over a
   literal URL, regenerates, verifies, and commits only when bytes changed. It
   requests `contents: write` and writes no path under `.github/workflows/`.
   It fails without committing when verification fails, and it fails when its
   own workflow file differs from the copy authored here.
3. `npx skills add wildcat-finance/skills-runtime --skill promise-machine`
   installs a package whose own `verify_runtime.py` exits 0.
4. This repository still advertises and serves its existing install, unchanged.
5. `.horos/boundary.json` regenerated.

Proved by `python3 -m unittest discover -s tests` exiting 0, by
`python3 plugins/horos/skills/horos/scripts/horos.py check .` exiting 0, and by
the install command in deliverable 3 followed by the installed
`verify_runtime.py` exiting 0.

**Files.** Created: `distribution/skills-runtime/sync.yml`, the canonical copy
of the destination's workflow, and `docs/skills-runtime-publication.md`
recording how the destination is bootstrapped and why its workflow needs a human
push. Changed: `.horos/boundary.json`.

**Tests.** One test asserting that the canonical workflow copy exists, requests
only `contents: write`, carries the repository guard, and names no path under
`.github/workflows/` as a write target. The install proof in deliverable 3 is a
recorded command run, not a suite test, because it reaches the network.

Runner contract for an audit fix: the exact command is
`python3 -m unittest discover -s tests -v > {report} 2>&1`, run from the
repository root with one `{report}` argument. The report format is stdlib
`unittest` verbose text. The report file is `.hexaemeron/step-2-report.txt`.

**Disciplines.** phylax: applies, because the step adds a scheduled job that
clones a URL, executes code from that clone, and commits with a token; the URL
is literal, the token is the job's own and holds only `contents: write`, and the
fork guard and workflow-drift check are the controls. ephoros: applies, because
the job runs unattended and must answer whether the published package is current
and whether the job is failing; the recorded source commit and the job's
non-zero exit are the signals. metron: none, no performance claim. elenchus:
applies, on the same terms as step 1. hypomnema: applies, because how the
destination is bootstrapped and why its workflow cannot be self-updating is
expensive to rediscover and belongs in `docs/`.

## Step 3: stop carrying the payload here

**Goal.** Remove the generated payload from this tree, stop advertising a skill
this repository no longer serves, repoint the documented install, and record the
reversal.

**Entry.** Step 2's branch, with the destination published and proven
installable.

**Exit.** Seven deliverables:

1. The 995 generated files under `.agents/skills/promise-machine/runtime/` are
   removed. The four authored files under `.agents/` stay at their existing
   paths, so `repo_contract.py`, the Promise contract's closed quotable set and
   `plugins/sapheneia/tests/test_sapheneia.py` all still resolve.
2. `.gitignore` ignores the generated runtime directory, so a local `sync` does
   not reintroduce it.
3. `skills.sh.json` no longer groups a skill this repository cannot serve.
4. `INSTALL.md` and `README.md` carry
   `npx skills add wildcat-finance/skills-runtime --skill promise-machine`, and
   no longer instruct an install from this repository.
5. The footprint guard added for ADR-054 is removed, because it measures a tree
   that no longer holds the payload.
6. A decision record supersedes ADR-054 explicitly, states the accepted hourly
   lag, names the destination, and states that a destination workflow change
   needs a human push because `GITHUB_TOKEN` cannot write one.
7. `.horos/boundary.json` and `.dead-code/baseline.json` regenerated.

Proved by `python3 -m unittest discover -s tests` exiting 0 with the payload
absent, by `python3 plugins/horos/skills/horos/scripts/horos.py check .` exiting
0, and by `git ls-files .agents | wc -l` reporting 4.

**Files.** Removed: `.agents/skills/promise-machine/runtime/**`. Changed:
`.gitignore`, `skills.sh.json`, `INSTALL.md`, `README.md`,
`tests/test_skills_sh_package.py`, `.horos/boundary.json`,
`.dead-code/baseline.json`, and `docs/decisions/ADR-054-keep-the-generated-skills-sh-payload-in-tree.md`
gaining its superseded status. Created: one decision record under
`docs/decisions/`.

**Tests.** The package tests continue to assert every guarantee against a
generated tree. One test asserts that the repository no longer advertises a
skill it does not carry, and one asserts the generated runtime directory is
ignored. The ADR-054 footprint guard is removed rather than repointed.

Runner contract for an audit fix: the exact command is
`python3 -m unittest discover -s tests -v > {report} 2>&1`, run from the
repository root with one `{report}` argument. The report format is stdlib
`unittest` verbose text. The report file is `.hexaemeron/step-3-report.txt`.

**Disciplines.** phylax: none, the step opens no boundary; it removes files and
edits prose and configuration. ephoros: none, nothing this step produces runs
unattended. metron: none, no performance claim; the size reduction is the
change's purpose rather than a budget it must hit. elenchus: applies, on the
same terms as step 1. hypomnema: applies, because reversing ADR-054 is expensive
to reverse again and its record's home is `docs/decisions/`.

**Ordering note.** The Horos boundary is regenerated last, and only after
`git add`, because the scan walks the tracked universe and a scan run before
staging describes the previous tree. The root suite is never run from a git hook
in this repository.
