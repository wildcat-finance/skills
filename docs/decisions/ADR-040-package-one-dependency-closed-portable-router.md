# ADR-040: Package one dependency-closed portable router

## Status

Accepted, 2026-08-27. Extended by ADR-054, which records why the generated
payload stays in this tree and what its per-clone cost is.

## Context

Agent Skills discovery finds the Promise Machine router and the canonical
plugin skills in this repository. An isolated install copies only the selected
skill directory. The router previously depended on root and plugin contracts
outside its directory, so `npx skills add wildcat-finance/skills --skill
promise-machine` produced a readable router with none of the law, runtime
contracts, canonical skills, or scripts it was required to load. Installing a
specialist directly has the same parent-directory problem.

The root law must remain authored once, plugin-local copies must remain
byte-identical, vendored Pashov skills must remain untouched, and the portable
router must not become another behavioural identity. The supported install
also needs to stay distinct from the user's target repository: a target's own
`AGENTS.md` cannot stand in for this suite's runtime contract.

## Decision

The sole `.agents/skills/promise-machine/` entry is the supported skills.sh
package. Its authored router detects a real source checkout by the suite law
and complete plugin topology. Otherwise it loads an installed adapter, verifies
a generated byte manifest, and treats its local `runtime/` directory as the
distribution root. Source-layout routes map to byte-identical plugin contracts
and canonical skill files inside that runtime.

`scripts/portable_promise_machine.py` owns the generated payload. It copies the
root law, collective identity, root runtime contract, the root observation
tools needed by Fiat, and every operational plugin file. It records source
path, size, and SHA-256 digest for every copy. Horos scans the install-shaped
payload and its result becomes a generated, manifested reading boundary inside
the package. Host manifests, plugin development suites, historical audit
records, and Alexandria's 16 MB Compound v3 Phase 0 trace inputs and built
release remain in the full checkout. The example explanation and rebuild
entrypoint still ship. The installed adapter names the omitted data and refuses
an operation that needs it.

The skills.sh page groups only `promise-machine` as the supported collective
install. Canonical specialist directories remain discoverable source entries
and appear below that group; the page does not present them as
dependency-complete packages.

## Alternatives

- Leave the router source-relative. That keeps no generated payload, but a
  successful installer still produces an unusable result.
- Fetch contracts and scripts after installation. That makes selection depend
  on mutable network content and removes the offline policy boundary.
- Duplicate a self-contained runtime under every canonical skill. That creates
  many package identities, multiplies generated bytes, and would require
  changing the untouched vendored skills.
- Copy the entire repository beneath the router. That preserves every
  development and evidence surface, but duplicates roughly 84 MB, including
  large generated views and repeated trace objects that ordinary operation
  does not load.
- Use links from the router to files outside its directory. Copy-mode
  installers do not preserve that parent layout, and link handling differs
  between hosts.

## Consequences

One skills.sh command installs a locally verifiable collective runtime. The
canonical root and plugin files remain the only authored behaviour; generated
copies are classified as such and a repository test refuses byte drift, path
escape, an altered omission boundary, or an incomplete install.

The installed verifier establishes internal agreement with its included
manifest. It does not authenticate the publisher or source commit; that claim
would need evidence outside the package it is meant to verify.

The installed package is larger than a prose-only skill because it carries the
scripts, schemas, examples, catalogues, and sibling contracts its routes need.
It is intentionally smaller than a source checkout. Development, audit, or
the omitted Alexandria demonstration still requires cloning the repository.
Changing any copied source requires regenerating the payload and Horos reading
boundary before the root suite can pass.
