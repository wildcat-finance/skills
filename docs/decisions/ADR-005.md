# ADR-005: Imprimatur -- the lexical gate in the Aegis chain

## Status

Accepted, 2026-08-19.

## Context

The Aegis review-and-release chain governs prose that ships. Imprimatur is
the first gate: it runs a banned-lexicon lint over every file before that
file reaches vulgate and any other consumer. It refuses one thing -- words
whose presence indicates machine prose rather than human writing -- and does
it with a blocking exit code. This record captures the gate's three
enforcement tiers, what qualifies as evidence for a gated term, and the
mechanical subset that makes the gate reliable enough to run on every
commit.

## Decision

### The three passes

Imprimatur runs three passes in a fixed order. The order matters because
each pass narrows the set of hits the next pass must consider.

**Hard pass.** Terms with no defensible use. Any hit on a hard-banned token
is a defect -- no synonyms from the same family, no justification, no
exception. The hard list is organised by family so that banning one token
does not invite its neighbour. A model banned for "load-bearing" will
say "does the heavy lifting"; the family-level ban blocks that too.

**Gated pass.** Terms of art that are real in context. A gated term
carries no automatic defect; it requires evidence in the same sentence.
A numeral, a backticked identifier, a hex address, a CamelCase name, or
a system from the allowlist satisfies the gate. Intensifiers such as
"materially", "significantly" and "fundamentally" require a numeral
because each promises a magnitude; if no number can follow, the word is
decoration and must go.

**Structural pass.** Formulae, not vocabulary. A structural hit flags a
pattern that appears in the same places regardless of the words --
negation-correction, bold-lead bullets, cadence repetitions. The hit
needs a decision: rewrite the pattern or accept it for a stated reason.

### What the gate accepts as evidence

A gated term passes when the sentence holding it contains a numeral, a
backticked identifier, a file path, a hex address, a CamelCase identifier,
or a system named in the allowlist. It also passes when the term is
immediately followed by its own definition. Anaphora is honoured: an open
pronoun inherits the previous sentence's evidence.

### What the gate protects from over-correction

The lexicon exists to remove filler, not precision. Qualifiers that carry
scope, causality, risk or legal meaning survive any rewrite. Statements
of what was and was not verified survive because they are truthfulness
defects, not style ones. Named entities, numbers, dates, citations and
quotations survive; quoting slop to discuss it is legitimate.

### Mechanical subset

`imprimatur.py` implements the three passes as a CLI. It reads one or
more files, runs all three passes, and exits 0 on no hits. A threshold
parameter controls the score at which it exits 1. A `--hard-only` fast
path supports hook-gate use. The output includes the defect list with
line numbers, severity, and rationale for each hit.

The test suite holds a false-positive corpus of legitimate technical prose.
A new term that fires on it must be gated, not banned. The run exits 0
only when the lexical gate finds nothing.

### Where it fits in Aegis

Aegis runs `imprimatur` before `vulgate` and before any reviewer sees
the file. The gate strips the machine-tell surface; vulgate then rewrites
what remains into the common tongue. Running `imprimatur` after vulgate
is redundant -- vulgate does not produce the banned vocabulary. Running
it before is necessary because a file with hard hits must be rewritten
before any downstream consumer sees it.

Imprimatur is the only gate in the chain with a blocking exit code.
`vulgate` has no code to run -- it is a directive applied at review time.
`ephoros` is not a gate at all; it is a checklist for instrumenting code.
The Aegis chain has one hard gate because the cost of letting AI prose
ship is higher than the cost of blocking on it.

### Why a hard gate, not a soft recommendation

A soft recommendation produces false positives and loses all its power.
A score of 60/100 is not a warning; it is an instruction to rewrite.
The gate exits 1, the file does not ship, and the author rewrites.
A gate that accepts 0 defects produces the only score that matters:
proof that the prose left the tree without known tells.

### Alternatives

1. **Run imprimatur as a non-blocking CI check.** Would prevent any file
   from landing, but would allow review to proceed on tainted prose.
   The gate's purpose is to prevent the file from reaching the reviewer
   at all.

2. **Merge imprimatur and vulgate into a single skill.** Would simplify
   the chain at the cost of conflating two operations: removing machine-tell
   vocabulary (imprimatur) and rewriting content-preserving voice (vulgate).
   Each has a different failure class -- removing machine-tell vocabulary versus
rewriting content-preserving voice -- and needs a different enforcement tier.

3. **Replace the lexical gate with an LLM-based classifier.** Would need
   an API, would carry a cost-per-file, and would produce a verdict without
   line numbers. The three-pass system needs none of those and runs locally.

## Consequences

- Every shipped file carries zero hard-ban hits. The gate is blocking.
- Gated terms can ship if the sentence provides evidence. That requires
  a reviewer to read each sentence with a banned term.
- Structural hits produce no exit code. A reviewer decides each pattern.
- The hard list must be updated with families, not loose tokens. A loose
  token becomes a synonym within a week and the ban is empty.
- A false-positive corpus must exist for every term added to the lexicon.
  If a term fires on it, the term is gated, not banned.
