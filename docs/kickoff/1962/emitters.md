# Wildcat V1 emitter declarations

Schema `wildcat.emitter-declarations.v1`. Source `wildcat-finance/wildcat-protocol` at commit `da74452aa7d1a0f024d99efd22cc6d950a8116b7`; builds are Sourcify records on chain 1, bound to the registry row `wildcat-v1-ethereum-mainnet` in `docs/kickoff/1359/targets.json`.

Mismatch classes: `topic0`, `log-arity`, `indexed-order`, `data-length`, `data-order`, `parameter-count`, `anonymous-declared`; a class found against a build's ABI is prefixed `abi:<contract>:`.

## Regenerating this table

```sh
python3 scripts/emitter_declarations_v1.py build --from-git <clone> --out docs/kickoff/1962/emitters.json --markdown docs/kickoff/1962/emitters.md
```

Verify without writing:

```sh
python3 scripts/emitter_declarations_v1.py check --from-git <clone> --table docs/kickoff/1962/emitters.json --markdown docs/kickoff/1962/emitters.md
```

Tie each build's ABI to the inputs the registry pins, with the registry's compiler `0.8.22+commit.4fc1097e`:

```sh
python3 scripts/emitter_declarations_v1.py crosscheck --solc <solc>
```

## Scope and limits

This is a static text comparison of source declarations, assembly emitters and the compiler ABI Sourcify retains for each deployed build. It runs no target code and makes no claim about runtime behaviour, deployed bytecode identity or capture completeness. Runtime emitter fidelity for V1 is the separate campaign in [#1964](https://github.com/wildcat-finance/skills/issues/1964); this table is its input, not its result.

V1 keeps no compiler input or output in its repository. Each build below is the verified Sourcify record of a contract the registry names, and the table keeps Sourcify's match status for it. The market and controller builds are the records of the first instance the registry lists; the registry records that every instance reproduces its one template from the factory's input. The standard input digest is the SHA-256 of `json.dumps(stdJsonInput, sort_keys=True, separators=(',', ':'))`, the registry's canonical form, and the ABI digest applies the same form to the compilation target's ABI.

Source commits are per component and come from the registry. The market, controller, factory and arch controller are built from `da74452a`, the commit the scan reads. The sanctions sentinel is built from `6164ddd4`, whose sources differ from `da74452a` only in their licence comments. The lens has no single source commit: the registry's best match is `488b30d0`, at 40 of 46 in-tree sources. Four of the other six match only `da74452a`, and `MarketErrors.sol` and `MarketEvents.sol` differ from every commit by one added licence line. The binding column of the source-file table shows, per build, whether each scanned file is equal, differs only in comments, differs, or is absent.

Reached by names the builds whose compilation target inherits, directly or through its bases, a contract that calls the emitter. This is narrower than the V2 table's build-level rule: the V1 factory's input carries the market sources because it embeds the market's creation code, but the factory never runs a market emitter.
