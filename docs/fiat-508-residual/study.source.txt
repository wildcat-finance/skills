### Confinement module specification

The implementation entrypoint will be a Fiat `worker-exec` supervisor launching one declared executable worker command under `/usr/bin/sandbox-exec`. The worker process and every enabled executor must descend from that launch. An executable shell, Python and patch worker is sufficient for the first prototype; a production model backend is not claimed. External MCP, app, command and other host deputies are unavailable. Unsupported operating systems, capabilities or launch policies refuse before the worker starts. This adds a new enforced execution path; it does not retrofit this conversation's tools.

The launch request binds the absolute execution root, worker argv, executable identities, policy digest, allowed tool inventory, deadline and output cap. Clear inherited authority and close descriptors; deny network and host IPC by default. Permit only the declared scratch root; the live run's `.hexaemeron`, worktree `.git` pointer, shared Git directory and aliases remain denied. Disposable fixture repositories may own their own `.git` inside scratch; those are data, never the live run metadata. Set child `TMPDIR` inside scratch. Keep controller metadata, shared Git, signing and receipts outside the worker. Relative source-owned report declarations remain unchanged: the dispatcher resolves declared operands to absolute paths and validates them before execution. The OS denies resolved out-of-root writes even in arbitrary child code; it cannot prove that every syscall argument was spelled absolutely.

Workers operate in disposable scratch beneath the target. Declared study, audit and report outputs go to the worker candidate-output subtree; the controller verifies and promotes their immutable snapshot to the declared `.hexaemeron` destination. Workers never write that live state directory directly. Guard destination substitution and preserve source-owned Elenchus declarations. The controller admits only bounded regular-file bytes copied through descriptor-bound, no-follow reads into controller-owned staging after the launch returns. It hashes and verifies that private snapshot before applying an approved manifest. Worker exit alone never certifies the mutable scratch tree. Symlinks, devices, metadata paths and stale admission identities refuse. A detached descendant can keep changing scratch but cannot reach the admitted snapshot or controller state; uncertain cleanup is recorded and refuses subsequent reuse of that scratch. Whole-path acceptance must demonstrate this separation with a `setsid` descendant. Process-group killing alone is insufficient.

The stronger saved `host-dispatch-probe.py` and result add a default-deny policy, clean environment, closed inherited descriptors and a denied loopback connection to the five filesystem specimens. They establish those six observations only. Full dispatch, IPC/deputy exclusion, metadata protection, inherited-descriptor handling and stable admission remain required implementation conformance.

Apple documents host directory exposure through configured directory-sharing devices. The vfkit project documents a VM command-line interface and explicit `virtio-fs` shares. These are implementation candidates, not conformance evidence for this task.

### Carryover module specification

Carryover reuses checkpoint export and halted-run retirement but adds a separate replacement admission. One bounded Markdown packet contains a closed JSON manifest and the complete cumulative changed-file payload, including deletions and executable modes, encoded as data. It binds source run, step, every round, original and fixed commit/tree identities, producer bytes and digests, finding occurrences, dispositions, guard identities and families. References preserve provenance; reconstructing the candidate cannot depend on an older packet. The manifest binds the monotonically numbered `<issue>-CARRYOVER[-N].md` sequence, exact packet digest, issue attachment identity and URL, archived controller evidence identities and a locally verified signed fixed-tree ref. Admission refuses missing or stale evidence, duplicate or non-successor sequence numbers, an attachment identity or digest mismatch, and an unverifiable signed ref. Packet creation and replacement admission never automatically close a pull request, delete a remote branch or merge. Reject symlinks, special files, duplicate destinations, Git/controller metadata and payloads above 64 MiB before applying anything.

Normalised findings use `(source_run, step, round, id)` with raw occurrence references, preserving repeated legacy rows rather than silently dropping them. Missing legacy evidence remains unknown and blocks dependent acceptance. Reconstruct the entire manifest on current base in private staging, recording every unchanged, transformed or conflicted path. Any conflict requires a complete revised mapping. No test, lint or acceptance gate runs on a partial reconstruction; bounded inert manifest validation necessarily precedes reconstruction. Execute all mapped inoculation guards, require actual non-skipped passes and family coverage, then request a new independent audit. Exhaustion remains finding-bearing; it never becomes clean through packet creation.

### Gate-validation module specification

Command validation parses every fenced command using a bounded grammar: literal argv, quoted operands and finite per-file loops over a declared list. Reject command substitution, arbitrary shell evaluation and unsupported forms. Checked-in CLI adapters validate arity and options without importing arbitrary target modules or executing runbook commands. Use harmless temporary specimens for supported parser probes. Bind original command bytes, adapter and CLI source digests, report substitutions and results at `done runbook`; replay refuses drift. Preserve Elenchus's source-owned input syntax and exact report bytes.
