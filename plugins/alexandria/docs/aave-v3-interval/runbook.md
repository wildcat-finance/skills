## What this runbook fixes once, for every step

**The precedent decides every open question.** On 2026-09-23 the maintainer,
Dr Laurence E. Day, ruled that each scope question in this run resolves to
whatever matches how #1731 captured Wildcat V1 and V2. Every step follows that
precedent except at the four departures study item 3 names: several segment
releases, an Aave-measured shard width and concurrency, a per-subject EIP-1967
epoch model with a venue-scoped upgrade-transaction rule, and a registry
generated from out-of-tree records checked against the in-tree row. A step that
finds a fifth departure stops and records it rather than choosing.

**The interval is the merged row's, not this runbook's.** The start block
16,291,071 and end block 26,022,093 are read from the `aave-v3` row of
`docs/kickoff/1359/targets.json` at each step's own base, with their hashes. The
segment count and widths are data Step 6 measures; no figure in this document is
a segment boundary.

**The endpoint and bearer token of the second transport are secrets.** Neither
may appear in any artefact this run produces: plan, registry, preflight record,
release, staging journal, receipt, test, fixture, commit message, pull request
text or issue comment. Both reach the process through environment variables
and nowhere else, and every record names its providers by class alone. No
shipped document names the private capture pipeline or its repository.

**The local archive node is read, never changed.** No step upgrades, restarts
or reconfigures it. Only Step 6 and Step 7 make RPC reads.

**Existing identities do not move.** The two Compound release identifiers and
both Wildcat examples' pinned releases, listed in study criterion 11, are
regression checks at every step that touches the collector.

**Digests are re-derived, not copied.** Any step whose Tests field names a
digest recomputes it from the file it names at that step's own base.

**All thirty-nine study risks are retained across every step.** Each step
that touches `plugins/alexandria` raises that package's version over its own
base, because the plugin-release gate requires a rise on every stacked step pull
request that changes a plugin tree; a step that changes no plugin tree owes no
rise and says so. Where a step adds, removes or edits a tracked file it
regenerates `.horos/boundary.json` first and `.horos/census.json` second, in
the commit that changes the tree. Every step passes its checks before commit
and stays open until ordered integration. Fiat owns receipts, signed commits
and publication.

**Ten gates fire on this run's scope.** The checked runner's plan for
`--scope alexandria --scope root` selects `alexandria-suite`, `root-suite`,
`dead-code-suite`, `dead-code-suppressions-check`, `demonstrations-suite`,
`front-door-check`, `joined-front-door-suite`, `lint-ephoros`,
`lint-hypomnema` and `lint-phylax`. The security suite is waived: this run
ships no Solidity and no Foundry or Hardhat project.

**Conformance cells are checked before the step they block.** A criterion
whose design record blocks `step:N` has its tests land in an earlier step, and
its resolver is run and its report written before Step N-1 is pushed. The
resolver is `.hexaemeron/design/conformance.py`, and its committed copy is
`plugins/alexandria/docs/aave-v3-interval/design/conformance.py`.
