## Step 1: Scaffold the collector's contracts and commit the design records

**Goal.** Land the shard planner, the `class-journals` staging writer and its

**Entry.** Run branch `fiat/395-resumable-ethereum-usdc-interval-collector` at

**Exit.** `plugins/alexandria/scripts/alexandria_lib/interval.py` exposes a pure
shard planner that turns a declared block interval and shard width into ordered,
bounded, non-overlapping shards covering the interval exactly, refusing a
reversed, empty, oversized or unbounded interval by name. It exposes the
`class-journals` staging writer selected by the design lock: one append-only
JSONL journal per evidence class under a confined staging root, each record
carrying the request bytes, the response bytes, the shard index and the class;
`commit` flushes and fsyncs every open journal and atomically replaces a
checkpoint naming the next shard, the last accepted block number and hash, and
each journal's committed byte offset; `resume` reads that checkpoint and

shard, and returns shard zero with every journal truncated to nothing when no
checkpoint exists. A kill between a record write and its checkpoint therefore
leaves nothing a resumed run keeps. Staging and output roots are resolved before
any containment comparison, so a `/var/folders` alias for `/private/var/folders`
does not refuse a contained path, and absolute paths, traversal and symlinks are
refused. Three closed schemas ship and are indexed in the plugin's schema

## Step 2: Discover implementation epochs from preserved chain evidence

**Goal.** Turn preserved `Upgraded(address)` logs, EIP-1967 slot reads and
runtime code reads into a contiguous, code-hash-bound epoch table covering a
declared interval, refusing an epoch it cannot bind.

**Entry.** Step 1's exit state on branch
`fiat/395-resumable-ethereum-usdc-interval-collector-step-1-scaffold-the-collector-s-contracts`,
with `interval.py`, the three schemas and both committed design records in the
tree and both suites green.

**Exit.** `interval.py` exposes epoch discovery over preserved bytes alone: it
takes the ordered `Upgraded(address)` logs for the proxy, the EIP-1967
implementation slot read at each boundary, and the runtime code read at each
implementation, and returns epochs whose inclusive start and end block numbers
tile the declared interval with neither a gap nor an overlap. Each epoch names
the chain, deployment and proxy, its start and end block numbers and hashes,
the upgrade transaction and log coordinates that opened it, the implementation
address and the SHA-256 of its runtime bytecode. It refuses, by name and
without a traceback: a boundary whose implementation slot is the zero address,
an implementation whose runtime code is empty, a slot read that is not a
32-byte word, logs that are unordered or carry a block number outside the
interval, an epoch table that leaves any block of the interval uncovered, and
any attempt to assign the current implementation to an unbound historical
boundary. `CometExt.version()` is not consulted, because the pinned source
returns the constant string `0`. The epoch table validates against
`interval-receipt-v1`. The conformance report
`.hexaemeron/reports/class-journals-epoch-contiguity.json` is produced by
`python3 .hexaemeron/design/conformance.py epoch-contiguity` and passes, which
is what opens step 3. Prove the exit with the same command battery as step 1,
plus that conformance command.

**Files.** Update `plugins/alexandria/scripts/alexandria_lib/interval.py`,
`plugins/alexandria/schemas/interval-receipt-v1.schema.json` and
`plugins/alexandria/tests/test_interval.py`. Create
`plugins/alexandria/tests/fixtures/usdc-epochs.json`. Update
`.horos/boundary.json` and `.horos/candidates.json` only with the required
complete staged-tree scan if their generated bytes change.

**Tests.** Add cases for a single-epoch interval, a two-upgrade interval whose
epochs tile it exactly, an interval whose first epoch opens before it and is
clipped to it, and the six refusals named in the exit. Add a case asserting the
zero-address slot and the empty-code read are refused separately, so a later
change cannot collapse them into one message. Add a case that the emitted table
validates against `interval-receipt-v1`. The Alexandria and root suites must
exit zero. The Elenchus runner contract is
`python3 plugins/alexandria/tests/run_tests.py --elenchus-report {report}`,
report format `unittest-json-v1`, report file `.elenchus/alexandria-unittest.json`.

**Disciplines.** phylax: the logs and reads are untrusted provider output, so
every field is shape-checked before it is believed and no value is coerced.
ephoros: none, this step emits no runtime signal of its own; the epoch table it
returns is consumed by step 3's loop rather than by an operator. metron: none,
no performance claim is made about an epoch table of at most a few dozen rows.
elenchus: each of the six refusals gets a guard that fails against a parent
that accepts the malformed input. hypomnema: the decision that an epoch is
bound by runtime code hash rather than by `version()` is recorded in the
collector document step 6 ships, because a reader will otherwise reach for the
version string.

## Step 3: Collect a bounded interval, resumably, from an injected transport

**Goal.** Walk the shard plan against a transport the caller supplies, binding
the end boundary to a named finality policy, checkpointing only after bytes are
fsynced, and rewinding when a boundary hash has changed.

**Entry.** Step 2's exit state on its branch, with epoch discovery in
`interval.py`, the epoch fixture in place, both suites green and
`.hexaemeron/reports/class-journals-epoch-contiguity.json` passing.

**Exit.** `plugins/alexandria/scripts/usdc_interval.py collect` walks the shard
plan for a declared interval and epoch table, issuing each shard's requests
through a transport object the caller supplies. The end boundary is resolved
under a named finality policy, `finalized`, `safe` or a stated confirmation
depth, and its block number and hash are bound before any shard is requested;
the policy name is recorded and never attributed to Compound. Each shard's
requests carry an identifier derived from the shard index and evidence class,
so an interrupted run and a clean run ask for the same bytes. A response is
refused, by name and without a traceback, when it exceeds the component byte
ceiling, fails strict bounded JSON parsing, carries a JSON-RPC error, is marked
truncated, or reports a result count at the provider's page limit; a refusal
writes an error receipt carrying the provider class, the attempt's status and
the unresolved block range, and never the endpoint, a header or a credential.
Each shard's boundary hash is checked against the previous shard's; a mismatch
rewinds to the last checkpoint whose accepted hash still matches and re-collects
from there rather than continuing across a fork. The command reads its endpoint
only from an environment variable, follows no redirect, and applies an explicit
timeout and total elapsed and byte ceilings. Killing the process at any point
and rerunning it produces journals byte-identical to an uninterrupted run. The
conformance report
`.hexaemeron/reports/class-journals-resume-rewinds-on-reorg.json` is produced by
`python3 .hexaemeron/design/conformance.py resume-rewinds-on-reorg` and passes,
which is what opens step 4. Prove the exit with the same command battery as
step 1, plus that conformance command.

**Files.** Create `plugins/alexandria/scripts/usdc_interval.py`,
`plugins/alexandria/tests/test_usdc_interval.py` and
`plugins/alexandria/tests/fixtures/usdc-interval-transport.json`. Update
`plugins/alexandria/scripts/alexandria_lib/interval.py`,
`plugins/alexandria/schemas/interval-plan-v1.schema.json`,
`plugins/alexandria/schemas/interval-checkpoint-v1.schema.json` and
`plugins/alexandria/tests/test_scaffold.py`. Update `.horos/boundary.json` and
`.horos/candidates.json` only with the required complete staged-tree scan if
their generated bytes change.

**Tests.** Add cases for a complete fixture collection; for a kill after a
committed shard and a kill mid-shard, each asserting the resumed journals are
byte-identical to the clean run's; for a changed boundary hash rewinding to the
last matching checkpoint and re-collecting; for each of the five response
refusals, asserting the error receipt exists and contains no endpoint substring;

`python3 plugins/alexandria/tests/run_tests.py --elenchus-report {report}`,

**Disciplines.** phylax: this step opens the transport boundary and the
credential boundary, so it carries byte ceilings, bounded strict parsing, no
redirect following, an explicit timeout, and a proof that no endpoint reaches a
file. ephoros: this is the step that runs unattended, so the checkpoint, the
error receipts and one sanitised non-zero exit line are the signals answering
the study's first two on-call questions. metron: the study's 5,000 ms
collect-and-resume budget is re-measured here against the delivered collector
rather than the probe. elenchus: the reorg rewind and each response refusal get
a guard that fails against a parent which accepts them. hypomnema: the finality
policy is operator policy the harvest document refuses to attribute to Compound,
so it is recorded in the collector document rather than implied by a default.

## Step 4: Reconcile the collected interval against a second provider

**Goal.** Run the completed interval past a second transport and record
agreement or a dispute, without letting either provider win by default.

**Entry.** Step 3's exit state on its branch, with `collect` delivered, both
suites green and
`.hexaemeron/reports/class-journals-resume-rewinds-on-reorg.json` passing.

**Exit.** `plugins/alexandria/scripts/usdc_interval.py reconcile` reads a
completed staging tree and a second transport, and compares the interval's
boundary hashes, its ordered block transaction hashes, and the identity tuple
`(blockHash, transactionHash, logIndex, address, topics, data)` for every log.
It emits a reconciliation receipt validating against `interval-receipt-v1` and
naming the compared identity count, the matched count, and every disputed
identity with both providers' bytes preserved. A disagreement is never resolved
by majority or by which transport answered first: the affected shard's coverage
status becomes `partial` when some identities matched and `failed` when the
boundary itself disagreed, and both responses are kept. A second transport that
cannot answer leaves the interval unreconciled and says so in the receipt
rather than silently passing. The conformance report
`.hexaemeron/reports/class-journals-reconciliation-refuses-mismatch.json` is
produced by
`python3 .hexaemeron/design/conformance.py reconciliation-refuses-mismatch` and
passes, which is what opens step 5. Prove the exit with the same command
battery as step 1, plus that conformance command.

**Files.** Update `plugins/alexandria/scripts/usdc_interval.py`,

`plugins/alexandria/tests/fixtures/usdc-interval-second-provider.json`. Update
`.horos/boundary.json` and `.horos/candidates.json` only with the required

## Step 5: Build the release and verify the interval offline

`alexandria-capture-plan/v1` document over the staging tree and calls the
existing `ingest` without changing it. The plan declares one component per
evidence class plus the pinned registry, the interval plan, the epoch table, the
shard receipt, the reconciliation receipt and the error receipt, and every
component's coverage collection, record count and declared block interval is
derived from the preserved bytes rather than asserted, so
`_validate_coverage_against_bytes` can refuse an inflated count. Every capture
