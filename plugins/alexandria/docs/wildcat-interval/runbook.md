## What this runbook fixes once, for every step

**Only one collector command can be declared on an Exit line.** The interface
adapter requires a builder that assigns a local named parser from a bare
argparse constructor and then only adds arguments. Of the collector's CLIs only
the runner registered above satisfies it; `usdc_interval.py`, `alexandria.py`,
`design_evidence.py` and every example demonstration were each tested and
refused, as was every other top-level function in those four modules, 61
candidates with none accepted. All four modules are unchanged at the base
commit. Every other command is therefore named in a step's Tests field with the
output and exit status it must give, and is run as part of that step's evidence.

**The interval is not this runbook's decision.** Selecting each estate's start
block, end block and shard width belongs to the capture maintainer, as the
issue's own boundary records. No block range written anywhere in this document
is an authorised interval. Where a collection step names a pair it is labelled a
worked example, present only so its Tests field has arithmetic to check, and the
step commits whatever interval the maintainer supplies. Each collection step's
Tests field checks the four admissibility conditions against the plan the step
actually commits, not against the worked example.

**The endpoint and bearer token of the second transport are secrets.** Neither
may appear in any artefact this run produces: not in the plan, registry,
release, staging journals, receipts, tests, fixtures, commit messages, pull
request text or issue comments. Both reach the process through environment
variables and nowhere else, and each preserved release names its providers by
class alone.

**Every capture and digest produced before this run is void and replaceable.**
The Compound release identifier and the two recorded refusal strings are kept as
regression checks because they cost nothing, not as constraints the design is
shaped around.

**Digests are re-derived, not copied.** The base moved twice while the study was
written, and two of the six merged records it reads moved again on `main` at
`0dd41be5c10bc83d3df33c9fdca3d385264059ba` without changing any address, subject
count, deployment block, code digest, list digest, row status or exclusion. Any
step whose Tests field names a digest says how to recompute it, and the step
re-reads its own inputs at its own base rather than trusting a table written
earlier.

**All thirty-two study risks are retained across every step.** Each step that
touches `plugins/alexandria` raises that package's version over its own base,
because the plugin-release gate requires it of every stacked step pull request
that changes a plugin tree; a step that changes no plugin tree owes no rise and
says so. Where a step adds, removes or edits a tracked file it regenerates
`.horos/boundary.json` first and `.horos/census.json` second, in the commit that
changes the tree, because the census reads the boundary and a census written
first records the previous tree while every gate reads green. Every step passes
its checks before commit and stays open until ordered integration. Fiat owns
receipts, signed commits and publication.

**Ten gates fire on this run's scope.** `python3 scripts/run_checks.py --scope
alexandria --scope root --plan` selects `alexandria-suite`, `root-suite`,
`dead-code-suite`, `dead-code-suppressions-check`, `demonstrations-suite`,
`front-door-check`, `joined-front-door-suite`, `lint-ephoros`, `lint-hypomnema`
and `lint-phylax`. The Alexandria suite holds 694 tests at the base commit, and
that is the entry state Step 1 starts from. Three named gates sit inside those
suites: the Horos reading boundary at `tests/test_boundary_currency.py`, the
Horos census currency at `tests/test_demonstrations.py`, and the demonstration
ledger at `plugins/alexandria/skills/alexandria/DEMONSTRATION.md`, which a new
example must be registered in. The security suite is waived: this run ships no
Solidity and no Foundry or Hardhat project.

## Two readings where the study and the tree disagree

Both are recorded here rather than resolved silently, because each changes what
a step writes.

`docs/adr/<number>-venue-dispatch-for-the-interval-collector.md`. There is no
`docs/adr` directory in this repository. Decision records live in
`docs/decisions/` as `ADR-<number>-<slug>.md`, and a record whose number is not

runbook therefore keeps the study's slug and uses the repository's own home and

sentence about allocating and re-checking the number by hand describes the older
